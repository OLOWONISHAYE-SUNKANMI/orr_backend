# ORR Solutions Database Schema Overview

The ORR backend uses PostgreSQL and is built on Django, logically divided into several key domain apps. All primary models inherit from a common `Audit` base class to provide standard `created_at` and `updated_at` timestamps.

## 1. Authentication & Security
- **`django.contrib.auth.models.User`**: Standard Django User model.
- **`django_otp.plugins.otp_totp.models.TOTPDevice`**: Links MFA devices to users.
- **`SystemConfig` (`admin_portal`)**: Singleton configuration table for global security settings (e.g. `mfa_enforced_roles`, `session_timeout`, `ip_bounds_restricted`).
- **`SecurityAuditLog` (`admin_portal`)**: Write-only log for security events (logins, system changes) with IP address, user agent, and metadata tracking.
- **`AuditLog` (`admin_portal`)**: Global audit trail generated by `post_save` and `post_delete` signals on models inheriting from `Audit`, tracking CRUD operations across the system.
- **`AdminSession` (`admin_portal`)**: Tracks active administration sessions and IP addresses.

## 2. User Profiles & Roles
- **`AdminRole` (`admin_portal`)**: Defines permission sets (e.g., `super_admin`, `admin`, `content_editor`, `operator`).
- **`AdminProfile` (`admin_portal`)**: Extends `User` with an `AdminRole`, department, and phone details.
- **`Profile` (`client`)**: Client user profile storing personal, location, and bio information.
- **`Client` (`admin_portal`)**: Organizational information for clients, mapping them to business pillars and lifecycle stages.
- **`Consultant` (`consultation`)**: Consultant profiles including skills, availability, and onboarding status.

## 3. Client Requests & Workflows
- **`ClientRequest` (`client`)**: Represents an inbound service request.
  - **State Machine**: `draft` → `submitted` → `pending_orr_review` → `approved_for_meeting` → `rejected` → `approved_for_pm_assignment` → `assigned_to_pm` → `converted_to_project`
- **`ClientRequestDocument` / `ClientRequestVersion` (`client`)**: Tracks attachments and historical versions of the request.
- **`OnboardingQuestionnaire` (`client`)**: Domain-specific questionnaire filled by clients upon sign-up.

## 4. Project Management (PM)
- **`PMProject` (`pm`)**: Represents an active, approved engagement managed by a Project Manager.
  - **State Machine**: `draft` → `awaiting_client_confirmation` → `active` → `delivered` → `completed` → `closed` → `archived`
- **`PMTask` (`pm`)**: Granular tasks assigned to users (clients, consultants) under a project.
  - **State Machine**: `pending` → `in_progress` → `under_review` → `approved` → `completed`
- **`PMAssignment` (`pm`)**: Maps a consultant to a project with a specific fee structure and scope.
- **`PMOpportunity` (`pm`)**: Published RFPs for consultants to bid on internal project needs.

## 5. Communications & Support
- **`Ticket` / `TicketMessage` (`admin_portal`)**: Support ticketing system with assigned admins, SLAs, and message history.
  - **State Machine**: `new` → `in_progress` → `resolved` → `archived`
- **`Meeting` (`admin_portal`)**: Virtual consultations integrating with Zoom/Google Meet.
  - **State Machine**: `requested` → `scheduled` → `completed` → `cancelled`
- **`ContactMessage` (`client`)**: Messages originating from the public contact forms, often converted to `Ticket`s.

## 6. Financials & Wallet
- **`Invoice` / `InvoiceItem` (`payment`)**: Stripe-linked billing records for clients.
- **`Wallet` / `WalletTransaction` (`admin_portal`)**: Pre-paid credit system for clients to fund consultations and project work. Balances are strictly validated.
- **`PaymentDispute` (`admin_portal`)**: Tracks chargebacks and billing disputes.
- **`ProRataApproval` (`admin_portal`)**: Dual-approval workflow models for consultant payouts and milestone billing.
- **`ApprovalQueue` (`admin_portal`)**: Generic dual-approval system for sensitive financial actions.

## 7. Content Management (CMS)
- Models to serve the marketing and informational pages of the application (`admin_portal.models_cms`).
- Includes `HomePage`, `ServicesPage`, `HowWeOperatePageContent`, `FAQ`, `BlogPost`, `Testimonial`, `ServiceCard`, etc.
- Uses `django-modeltranslation` to support multilingual fields (e.g., `title_en`, `title_it`).

## 8. Document Vault
- **`VaultFolder` (`admin_portal`)**: Logical folder structures.
- **`ClientDocument` (`admin_portal`)**: Files associated with a client.
- **`StudioDocument` / `DocumentVersion` (`admin_portal`)**: Controlled documents with version tracking.
